# 다국어 홈페이지 정보 구조 설계

작성: hy0909 · 2026-10-13

한국어 홈페이지를 영어·일본어·독일어 버전으로 다시 설계한 내용이다. 같은 회사 이야기를 하되 나라마다 먼저 보여 줄 것, 글의 양, 신뢰를 얻는 방법을 다르게 잡았다.

## 1. 주소와 언어 판단

| 주소 | 내용 |
|---|---|
| `/` | 언어를 판단해 해당 폴더로 바로 보내는 첫 화면 |
| `/en/` | 영어. 판단이 안 되면 여기로 간다 |
| `/ja/` | 일본어 |
| `/de/` | 독일어 |
| `/ko/` | 개선 전 한국어 원본. 비교용으로 그대로 둔다 |

언어는 접속한 국가로 정한다.

| 접속 국가 | 언어 |
|---|---|
| 한국 | 한국어 |
| 일본 | 일본어 |
| 독일, 오스트리아, 스위스, 리히텐슈타인 | 독일어 |
| 그 밖의 모든 국가 | 영어 |

주소에 `?lang=ja`처럼 언어를 적으면 국가와 상관없이 그 언어로 연다. 발표나 공유용 링크에 쓴다.

GitHub Pages에는 서버가 없어서 국가는 외부 서비스로 알아낸다. 먼저 Cloudflare 접속 정보를 묻고, 답이 없으면 GeoJS에 다시 묻는다. 둘 다 1.5초 안에 답하지 않으면 브라우저 언어 설정으로 대신 판단한다. 이때 방문자 IP가 두 서비스로 넘어가기 때문에 독일어 개인정보 처리 방침 6항에 적어 두었다.

언어 메뉴에서 다른 언어를 고르면 같은 페이지의 그 언어 버전으로 간다. 그 언어에 같은 페이지가 없으면 메인으로 간다. 고른 언어는 저장하지 않는다. 저장해 두면 다음 방문 때 국가보다 앞서 적용돼서, 접속 국가와 다른 언어가 열리는 문제가 생긴다.

## 2. 나라별로 다르게 잡은 기준

구성 차이는 두 가지 연구 결과를 기준으로 정했다. 하나는 에드워드 홀의 고맥락·저맥락 문화 구분이고, 다른 하나는 홉스테드 문화 차원 점수다. 출처와 근거 등급은 [localization-rationale.md](localization-rationale.md)에 정리했다. 개인주의 점수는 2023년에 개정돼 미국과 일본의 차이가 거의 없어졌기 때문에 차별화 근거로 쓰지 않는다.

| 기준 | 미국·영어권 | 일본 | 독일 |
|---|---|---|---|
| 맥락 | 저맥락. 말한 그대로 전달 | 고맥락. 관계와 배경을 먼저 | 저맥락. 사실과 근거를 정확히 |
| 불확실성 회피 (홉스테드) | 46, 낮음 | 92, 매우 높음 | 65, 높음 |
| 개인주의 (홉스테드, 2023 개정값) | 60 | 62 | 79 |
| 홈페이지에 기대하는 것 | 나에게 어떤 이득이 있는지 빨리 | 믿을 만한 회사인지, 빠짐없는 정보 | 어떻게 작동하는지, 숫자의 출처 |

이 기준을 화면 구성으로 옮기면 아래와 같다.

| 항목 | 영어 | 일본어 | 독일어 |
|---|---|---|---|
| 첫 화면 | 어두운 도시 사진 위에 큰 문구 하나와 데모 요청 버튼 | 밝은 배경, 문구 옆에 도입 실적과 바로가기 메뉴 | 차분한 도시 사진, 무엇을 하는 회사인지 사실 그대로 |
| 정보량 | 적게. 섹션마다 메시지 하나, 여백 넓게 | 많게. 표·목록·공지를 한 화면에 촘촘히 | 중간. 사양표와 계산 근거를 빠짐없이 |
| 글 길이 | 짧은 문장, 효과 위주 | 정중한 문장, 설명을 길게 | 정확한 용어, 과장 없는 문장 |
| 신뢰를 얻는 방법 | 성과 숫자, 대표 사례 하나를 크게 | 도입 기관, 회사 개요표, 연혁, 특허, 자주 묻는 질문 | 측정 기준과 출처, 개인정보 처리 방식, 특허 |
| 문의 방법 | 데모 요청 하나로 모음 | 자료 요청과 문의를 나눠서, 전화번호도 함께 | 문의 양식과 개인정보 동의 확인 |
| 사람 이미지 | 여러 인종이 섞인 서양 팀 | 동양인 | 서양인 |
| 글꼴과 모양 | Inter, 큰 제목 | Noto Sans JP, 본문 15px 촘촘하게 | IBM Plex Sans, 장식 적게, 모서리 각지게 |
| 법적으로 꼭 필요한 페이지 | 없음 | 없음 | Impressum(회사 표기), Datenschutz(개인정보 처리 방침) |

색은 나라별로 바꾸지 않는다. 한국어 사이트와 CI에 정한 브랜드 컬러(Deep Navy #05060D, Sound Sky #7FA8FF, Signal Violet #A46BFF, Pulse Pink #F45FC8와 그라데이션)를 모든 언어에 그대로 쓴다. 색 값은 `assets/css/global.css` 한 곳에만 있고, 언어별 `locale.css`에는 색을 적지 않는다.

## 3. 사이트맵

게시판(공지·뉴스·CI)은 영어·일본어·독일어에만 있다. 관리자에서 글을 쓸 때 언어를 고르면 그 언어 사이트의 게시판에만 올라간다. CI는 그 언어로 쓴 항목이 없으면 한국어 항목을 보여 준다. 한국어에는 게시판과 채용 페이지가 없다(2026-10-15에 사용자 지시로 삭제). 한국어 회사소개는 하위 목차 없이 한 페이지다.

| 페이지 | 파일 | 영어 | 일본어 | 독일어 | 한국어 원본 |
|---|---|---|---|---|---|
| 메인 | `index.html` | Home | トップ | Startseite | 메인 |
| 솔루션 | `solutions.html` | Solutions | ソリューション | Lösungen | 솔루션 |
| 기술 | `technology.html` | Technology | 技術 | Technologie | 기술 |
| 도입 사례 | `cases.html` | Case studies | 導入事例 | Referenzen | 도입 사례 |
| 회사 소개 | `company.html` | About | 会社情報 | Unternehmen | 회사소개 |
| 문의 | `contact.html` | Book a demo | お問い合わせ・資料請求 | Kontakt | 도입 문의 |
| 회사 표기 | `impressum.html` | | | Impressum | |
| 개인정보 처리 방침 | `privacy.html` | | | Datenschutz | |
| 게시판 | `notice.html`, `news.html`, `ci.html` | News & notices | ニュース・お知らせ | Aktuelles | 없음 |
| 채용 | (삭제) | | | | 없음 |

메뉴 순서도 나라마다 다르다.

| 순서 | 영어 | 일본어 | 독일어 |
|---|---|---|---|
| 1 | Solutions | ソリューション | Technologie |
| 2 | Technology | 導入事例 | Lösungen |
| 3 | Case studies | 技術 | Referenzen |
| 4 | About | 会社情報 | Unternehmen |
| 5 | Board | 掲示板 | Aktuelles |
| 오른쪽 버튼 | Book a demo | 資料請求 | Kontakt |

일본어는 도입 사례를 기술보다 앞에 둔다. 일본 기업 담당자는 다른 기관이 이미 쓰고 있는지를 먼저 보기 때문이다. 독일어는 기술을 맨 앞에 둔다. 작동 원리를 납득해야 다음 단계로 넘어가는 경향이 있어서다.

## 4. 메인 페이지 섹션 순서

| 순서 | 영어 | 일본어 | 독일어 |
|---|---|---|---|
| 1 | 히어로: 큰 문구, 데모 요청 | 히어로: 문구, 자료 요청·문의 버튼, 도입 실적 배지 | 히어로: 하는 일을 한 문장으로, 문의·기술 자료 버튼 |
| 2 | 성과 숫자 3개 | 바로가기 타일 (솔루션 3개, 사례, 회사 개요) | 핵심 수치와 출처 |
| 3 | 작동 방식 3단계 | 새 소식 목록 | 작동 원리 3단계와 그림 |
| 4 | 솔루션 카드 3개 | 해결하려는 문제와 통계 | 기술 사양표 |
| 5 | 대표 사례 하나 크게 | 솔루션 3개와 도입 절차 | 활용 분야 3개 |
| 6 | 기존 측정소와 비교 | 도입 사례 2개와 숫자 | 실증 결과와 측정 조건 |
| 7 | 문의 띠 | 기술과 특허 | 개인정보를 지키는 설계 |
| 8 | | 회사 개요표와 연혁 | 회사와 특허 |
| 9 | | 자주 묻는 질문 | 문의 띠 |
| 10 | | 문의 띠: 자료 요청, 전화, 양식 | |

## 5. 콘텐츠 원칙

- 내용은 한국어 원본(`/ko/`)과 IR 자료에 있는 사실만 쓴다. 번역이 아니라 그 나라 사람이 쓴 것처럼 새로 쓴다.
- 숫자에는 원본에 있는 출처와 조건을 그대로 붙인다. 민원 감소 60%는 설치 지역 한정이고 단속 없이 관측과 안내만 한 기간이라는 조건을 빼지 않는다.
- 원본에 없는 정보는 지어내지 않는다. 화면에는 `TBD`로 표시하고 아래 확인 목록에 올린다.
- 재무 정보와 투자 계획은 어느 언어에서도 공개하지 않는다.

## 6. 이미지

나라별 이미지 자리와 생성 프롬프트는 [image-prompts.md](image-prompts.md)에 정리했다. 지금은 Unsplash 무료 사진으로 자리를 채워 두었고, 생성한 이미지가 오면 파일만 바꾸면 된다.

## 7. 확인이 필요한 것

| 항목 | 쓰이는 곳 |
|---|---|
| 회사 영문 표기, 대표자 영문 이름 | 세 언어 회사 소개, 독일어 Impressum |
| 주소, 전화, 문의 이메일, 사업자등록번호 | 모든 언어 푸터와 문의 페이지. 비어 있으면 문의 양식이 동작하지 않는다 |
| 일본·독일 현지 대응 창구 여부 | 일본어 전화 문의, 독일어 Impressum의 EU 대리인 |
| 도입 절차 (상담 → 현장 조사 → 설치 → 운영) | 일본어 메인. 원본에 없어 일반적인 절차로 적어 두었다 |
| 소개 자료(PDF) 파일 | 일본어 자료 요청. 파일이 생기기 전까지는 문의 양식으로 받는다 |
| 개인정보 처리 방침 원문 | 독일어 Datenschutz. 법률 검토 전 초안이다 |
